01-flow

Use case: infographic-diagram. Asset: generated raster architecture illustration for Gambit's README. Audience: people who understand a web app but are new to agent harnesses.
Style: polished flat editorial diagram on a white background, zinc-gray outlines, dark text and restrained emerald green accents matching Gambit's existing UI. Plain large sans-serif typography readable at 800px display width. Landscape 1536x1024. Generous whitespace, crisp simple line icons, no gradients, shadows, mascots, decorative textures, logos, watermarks, or tables.
Architecture facts you MUST preserve: The Gambit harness is server application code around the agent. It supplies recent conversation context, saved records and roster facts. One OpenAI model chooses tools; Google ADK manages the repeated model/tool loop. Tools read facts, build proposals, find options and ask questions. Tools return results to the agent. Tools request trade validation only when a proposal needs checking, not for every question or search. Gambit owns lasting conversation history; ADK's session is temporary. Proposed changes are staged and saved only when the turn completes; failed turns keep earlier proposals intact. The browser shows live tool progress and finally a reply with cards or choices.
Constraints: no second agent, no separate interpretation model, no model-to-database-write arrow, no claim that the model decides trade legality, no implication of validation for every turn. Legible arrows must not intersect labels. Render specified labels exactly, with no invented paragraphs. Differentiate optional checks from the repeated agent/tool loop.
Layout concept 1: A very clear left-to-right STORY FLOW. Header "Gambit: from message to reply". Five broad stages across the landscape: "Your message", "Load context", a larger central grouped panel titled "Agent + tools", "Save finished turn", "Reply + cards or choices". Use one continuous emerald arrow between stages.
Inside the "Agent + tools" panel there are exactly two cards "Agent" / "OpenAI + Google ADK" and "Tools" / "Read • Build • Search", with two distinct opposing arrows labeled "Call" and "Result". Draw the loop clearly inside this stage. Above "Load context" a small "Conversation + roster facts" stack connects down ONLY to Load context; Load context then connects to Agent. BELOW Tools, a separate small "Trade checks" card connects to Tools with two arrows, with the visible caption "When needed". Never put checks on the main linear flow.
A light outline around all three middle stages is titled "Gambit harness". Input and output sit outside. Below the save stage: "Failed turns keep earlier proposals intact". Across the bottom a light horizontal strip labeled "Tool progress appears while the agent works". Large type and a compact amount of copy. Clear sequence and no arrow tangles. This is a pipeline with an embedded loop, not a circular hub.

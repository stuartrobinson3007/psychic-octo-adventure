## Implementation and asset provenance

The four scenario IDs point to existing local recorded conversations: finding and checking trades, player clarification, revising and undoing, and players with draft picks. Every recorded turn produces one request stage followed by one response stage. Nearby stages render lazily from `/ux-review-frame`, then clone the real DOM into a scriptless sandboxed HTML frame. Scripts, embedded frames and event-handler attributes are removed; action controls are inert and editable content becomes read-only. The presentation shell retains scenario and stage navigation, while the conversation screens support reading and scrolling.

The feature uses existing player images, team marks and Hugeicons through the production renderer. It creates no raster asset or new visual-world imagery, so no new generated-asset provenance entry is required. The review PNGs are evidence captures, not shipping assets. Recordings are loaded through the existing local review-data endpoint; browsing this viewer does not execute a model request. The route is available in development and displays an availability message in production.
